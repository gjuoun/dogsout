## 1. CLI 基本面

```sh
dogsout --help          # 子命令清单应正常打印
dogsout init            # 第一步！全新 vault（Touch ID / Secure Enclave，无密码）——所有命令都要先有 vault
echo "sk-FAKE-TEST" | dogsout set dogsout://dev/gh/token   # 值走 stdin，地址是完整 dogsout://vault/item/field
dogsout ls              # 应列出 dev vault 的 gh item
dogsout get dogsout://dev/gh/token          # 默认只出 sha256 指纹；--reveal 才出明文（应触发 Touch ID）
```

- ⚠️ **set 的第一个参数是完整地址** `dogsout://<vault>/<item>/<field>`，不是裸 alias——没 vault 时应报 `vault not found … run: dogsout init`（exit 1）

## 2. 审批窗（mygo 原生，重点体验）

```sh
DOGSOUT_HOME=/tmp/dog-test dogsout init
echo "sk-FAKE" | DOGSOUT_HOME=/tmp/dog-test dogsout set dogsout://dev/openai/token   # 假 key
DOGSOUT_HOME=/tmp/dog-test dogsout run -- dogsout get dogsout://dev/openai/token || true
```

- 期望弹出原生窗口（标题 dogsout-approve）：新 key 三态（批准|本次|拒绝）、TTL 六档默认 10m、底部「批准 N 个 / 全部拒绝」
- **试三个路径**：① 点「批准」→ 终端拿到 env 注入；② 点「全部拒绝」→ 进程拿不到 key 且退出码非 0；③ 直接点红叉关窗 → 应等同拒绝（fail-closed）
- ✅ 这是 1P 对标里我们自己的「人批准」环节，顺手感受下 mygo 的手感
